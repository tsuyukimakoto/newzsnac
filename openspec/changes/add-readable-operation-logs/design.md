## Context

動機は `proposal.md` を参照。現在の収集サイクルは情報源ごとの発見件数だけを返し、記事保存処理は記事 ID だけを返すため、新規件数を集計できない。分析クライアントは所要時間と token 数を任意の JSON テレメトリへ渡すが、記事を保存するワーカー層までメトリクスを返していない。推薦サービスは類似度を SQLite へ保存するだけで、推薦ジョブを実行するワーカーへ計算結果を返していない。

LM Studio の OpenAI 互換 Chat Completions は token 使用量を返す一方、公式に生成速度を提供するのは拡張 `stats.tokens_per_second` である。リクエスト全体の時間には入力処理やモデルロードも含まれ得るため、completion token 数を全体時間で割った値は生成速度として扱わない。

## Goals / Non-Goals

**Goals:**

- 処理ドメインから構造化された集計・メトリクスを返し、表示形式をログ専用モジュールへ集約する。
- テストでは時刻と出力先を差し替え、日時・整形・省略規則を決定的に検証できるようにする。
- 収集失敗と LLM 分析失敗を別々に扱い、現在の再試行動作を変えない。
- LLM の0から100の読む優先度と、埋め込み類似度による0から1の「読むべきかも？」スコアを異なるフィールドとイベントで表示する。

**Non-Goals:**

- 起動確認、CLI 応答など機械可読 JSON の形式変更。
- ログレベルの設定機構、ファイル出力、永続的な分析履歴の追加。
- 読書 UI や SQLite スキーマの変更。

## Decisions

### 共通の行フォーマッターを追加する

ログは `[MM-DD HH:mm:ss] LEVEL event key=value ...` とし、日時生成、文字列の引用、改行除去、時間表示を一つのモジュールで行う。呼び出し側で文字列を組み立てる案は表記揺れとテスト重複を生むため採用しない。

### 記事保存時に新規かどうかを返す

記事リポジトリへ ID と `created` を返す保存 API を追加し、既存の ID のみを返す API は互換性のため残す。収集コーディネーターは保存コールバックが返した新規数を情報源ごとの結果へ含め、サイクルで合計する。サイクル前後の総件数差を取る案は、将来収集が並行化された場合に別処理の挿入を数えるため採用しない。

### 成功した分析だけを記事単位で通知する

LLM クライアントに分析結果と応答メトリクスを返す詳細 API を追加し、既存 API は結果だけを返す互換ラッパーとして維持する。分析ワーカーはデータベース保存とジョブ完了後に記事単位の成功イベントを通知する。再試行へ移った失敗は成功ログを出さず、既存の詳細テレメトリが有効なら従来どおり原因を記録する。

### tok/s はサーバー値だけを使う

応答の `stats.tokens_per_second` が有限かつ0以上の場合だけ保持する。値がない場合はフィールドを省略する。API を生成速度取得のためだけに別エンドポイントへ移す案は、現在の OpenAI 互換 API と reasoning/JSON schema の動作を変えるため採用しない。

### 保存された推薦結果を記事単位で通知する

推薦サービスは、一つの推薦ジョブで保存した対象記事 ID、根拠記事 ID、類似度の配列を返す。ワーカーはジョブ完了後に各結果を成功イベントとして通知し、同じジョブで複数記事を再計算した場合は記事ごとに一行を出力する。閾値は読む画面へ表示するかの判定であり計算結果そのものではないため、閾値未満の類似度もログへ出す。SQLite をジョブ完了後に再検索する案は、どの結果がそのジョブで更新されたかを識別しにくいため採用しない。

分析ログでは LLM の判断を `priority`、推薦ログでは決定的な埋め込み計算結果を `score` と呼び、両者を同じフィールド名にしない。通知先の例外は捕捉し、完了済みジョブを再試行へ戻さない。

## Risks / Trade-offs

- [LM Studio の版によって OpenAI 互換応答に `stats` が含まれない] → tok/s は省略し、誤解を招く推定値を表示しない。
- [記事タイトルに改行や引用符が含まれてログを読みにくくする] → 空白を正規化し、上限で短縮して JSON 文字列として引用する。
- [10秒ごとの空ポーリングがログを埋める] → 取得対象が一件以上あったサイクルだけ収集完了を表示する。
- [関心変更による全件再計算で多数の推薦ログが続く] → 一行を記事単位に保ち、対象記事と根拠記事を追跡できるようにする。

## Migration Plan

データ移行は不要。コードを配備すると処理完了ログが追加される。ロールバックは新しいログ出力と結果フィールドを戻すだけで、SQLite の状態には影響しない。

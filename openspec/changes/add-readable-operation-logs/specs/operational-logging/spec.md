## Purpose

バックグラウンドの収集、記事分析、推薦計算について、処理量、結果、所要時間を起動中の端末から短時間で把握できる運用ログを提供する。

## ADDED Requirements

### Requirement: 短い日時付きの運用ログ
システムは収集、記事分析、推薦計算の運用イベントを、一行の人が読めるログとして出力しなければならない（SHALL）。各行はローカル時刻による `MM-DD HH:mm:ss` 形式の日時と、大文字のログレベルを含まなければならない（MUST）。

#### Scenario: info イベントの表示
- **WHEN** バックグラウンド処理が表示対象の処理を完了する
- **THEN** システムは `[MM-DD HH:mm:ss] INFO` で始まる一行を標準出力へ出力する

### Requirement: 収集結果の要約
システムは一つ以上の取得対象を確認した収集サイクルごとに、参照した情報源数、見つかった記事数、データベースへ初めて追加した記事数、失敗した情報源数、サイクル全体の所要時間を一行で出力しなければならない（SHALL）。取得対象がないポーリングでは完了ログを出力してはならない（MUST NOT）。

#### Scenario: 新規記事を含む収集
- **WHEN** 3件の情報源から合計12件の記事を見つけ、そのうち4件を新規記事として保存し、1件の情報源が失敗する
- **THEN** 収集ログは情報源数3、記事数12、新規記事数4、失敗数1、所要時間を含む

#### Scenario: 取得対象がないポーリング
- **WHEN** 収集サイクルで確認対象となる情報源が0件である
- **THEN** システムは収集完了の info ログを出力しない

### Requirement: 情報源取得失敗の表示
システムは個別の情報源取得が失敗した場合、他の情報源の収集を継続し、情報源 ID とエラー内容を日時付きの一行の warn ログへ出力しなければならない（SHALL）。

#### Scenario: 一部の情報源だけが失敗する
- **WHEN** 収集サイクル内の一つの情報源取得が失敗する
- **THEN** システムは `[MM-DD HH:mm:ss] WARN` で始まり情報源 ID とエラー内容を含む一行を出力し、サイクルの集計も出力する

### Requirement: 記事分析結果の表示
システムは LLM による記事分析が成功するたびに、記事 ID、改行を除去して適切な長さに短縮したタイトル、記事処理全体の所要時間、LLM が返した0から100の読む優先度を `priority` として一行で出力しなければならない（SHALL）。

#### Scenario: 記事分析が成功する
- **WHEN** 記事の LLM 分析と結果保存が完了する
- **THEN** 分析ログは記事 ID、タイトル、所要時間、0から100の `priority` を含む

#### Scenario: 記事分析が失敗する
- **WHEN** LLM 呼び出しまたは結果検証が失敗してジョブが再試行待ちになる
- **THEN** システムは成功を示す記事分析 info ログを出力しない

### Requirement: LLM 生成速度の正確な表示
システムは LM Studio の応答が生成速度を返した場合に限り、記事分析ログへ小数第1位までの tok/s を含めなければならない（MUST）。生成速度が返されない場合、リクエスト全体の所要時間から推定した tok/s を表示してはならない（MUST NOT）。

#### Scenario: 生成速度が返る
- **WHEN** LM Studio の分析応答に有限かつ0以上の tokens-per-second 値が含まれる
- **THEN** 記事分析ログはその値を小数第1位の tok/s として含む

#### Scenario: 生成速度が返らない
- **WHEN** LM Studio の分析応答に tokens-per-second 値が含まれない
- **THEN** 記事分析ログは tok/s フィールドを省略する

### Requirement: 「読むべきかも？」スコアの表示
システムは未読記事と「気になった」記事の推薦計算結果を保存するたびに、対象記事 ID、根拠記事 ID、推薦ジョブ全体の所要時間、-1から1の類似度を `score` として一行で出力しなければならない（SHALL）。類似度は推薦表示の閾値未満でも出力しなければならない（MUST）。

#### Scenario: 推薦スコアを計算する
- **WHEN** 対象記事と根拠記事の埋め込みから類似度を計算して推薦結果を保存する
- **THEN** `recommendation.complete` ログは対象記事 ID、根拠記事 ID、所要時間、-1から1の `score` を含む

#### Scenario: 推薦元の記事がない
- **WHEN** 対象記事に対して比較可能な「気になった」記事がなく推薦結果を保存しない
- **THEN** システムは対象記事の `recommendation.complete` ログを出力しない

#### Scenario: 推薦計算が失敗する
- **WHEN** 推薦ジョブが失敗して再試行待ちになる
- **THEN** システムは成功を示す `recommendation.complete` ログを出力しない

### Requirement: 既存の機械可読ログとの互換性
システムは既存の起動確認 JSON と、設定で有効化される詳細分析 JSON テレメトリを維持しなければならない（SHALL）。

#### Scenario: ワーカーを起動する
- **WHEN** 収集または分析ワーカーを起動する
- **THEN** システムは従来どおり起動状態を JSON で出力する

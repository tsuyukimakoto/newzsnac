## Why

現在のワーカー出力は起動状態や低水準の JSON テレメトリが中心で、収集や記事分析が何をどこまで処理したかを起動中の端末から把握しにくい。日常運用で確認したい件数、所要時間、分析結果を短く一貫した info ログとして表示する。

## What Changes

- すべての通常運用ログに短いローカル日時とログレベルを付ける。
- 収集サイクル完了時に、参照した情報源数、見つかった記事数、新規記事数、失敗した情報源数、所要時間を一行で出力する。
- 記事分析完了時に、記事 ID、短縮したタイトル、処理時間、LLM が返した0から100の読む優先度を一行で出力する。
- 推薦計算完了時に、対象記事 ID、根拠記事 ID、処理時間、-1から1の「読むべきかも？」類似度スコアを一行で出力する。
- LM Studio が生成速度を返した場合は tok/s を記事分析ログへ含め、返さない場合は不正確な推定値を表示しない。
- 起動確認や機械処理に使う既存の JSON ログと、明示的に有効化した詳細分析テレメトリは維持する。
- 非目標: ログの永続化、ローテーション、外部監視サービスへの転送、過去処理の統計画面は今回扱わない。

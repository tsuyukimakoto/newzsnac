## Context

現在の `src/main.ts` は3つの子プロセスを監督し、SIGTERM を受けると全子プロセスへ終了シグナルを伝播する。一方、別のシェルからその親プロセスを特定する記録と停止用タスクがない。設定は `config.ts` の既定値を `.env` と環境変数で上書きする方式に統一されている。

## Goals / Non-Goals

**Goals:**

- 既存のスーパーバイザーの終了処理を再利用し、別ターミナルから全サービスを停止する。
- 停止操作を繰り返しても成功する冪等なコマンドにする。
- テストや複数の作業コピーで実行記録が衝突しないよう保存先を設定可能にする。

**Non-Goals:**

- SIGKILL による自動的な強制終了は行わない。
- OS サービスとしての登録やバックグラウンド化は行わない。

## Decisions

### スーパーバイザーの PID を専用ファイルへ記録する

起動時に排他的作成を行い、PID と作業ディレクトリを JSON で保存する。停止コマンドはこのファイルだけを参照する。ポート検索や `pkill` は同じポート・プロセス名を使う無関係なプログラムを巻き込むため採用しない。

既存ファイルの PID が生存していれば二重起動として拒否し、生存していなければ古い記録として置き換える。スーパーバイザー終了時の削除では、現在の PID と一致する記録だけを削除し、後続プロセスの記録を誤って消さない。

### 停止コマンドは SIGTERM 後に終了を待つ

停止エントリーポイントは記録された PID へ SIGTERM を1回送り、一定時間プロセスの消滅を待つ。完了時は構造化された JSON を標準出力へ返す。時間内に終了しない場合はエラーにし、利用者の意図なく SIGKILL へ移行しない。

### 実行記録パスを共通設定にする

既定値を `data/newzsnac.pid` とし、`NEWSZNAC_PID_PATH` で上書きする。起動側と停止側が同じ設定ローダーを使うことで対象の不一致を防ぐ。既定の `data/` は既に Git 管理対象外である。

## Risks / Trade-offs

- [PID が極めて短時間に再利用され、古い記録が別プロセスを指す可能性] → 記録に作業ディレクトリを含め、停止側で現在の作業ディレクトリとの一致を必須にする。停止は専用ファイルがある場合だけ行う。
- [子プロセスが SIGTERM に応答せず停止が完了しない] → タイムアウトをエラーとして明示し、強制終了は利用者の判断に残す。
- [SIGKILL や電源断で記録が残る] → 次回起動時と停止時に PID の生存を確認して古い記録を除去する。

## Migration Plan

データ移行は不要。更新後の最初の `mise run start` から実行記録が作成される。更新前から残っているプロセスには記録がないため、いったん従来の方法で停止してから新しい起動コマンドを使用する。

## Why

`mise run start` で起動した常駐プロセスを、別ターミナルから確実にまとめて停止する手段がない。Web、収集ワーカー、分析ワーカーを残留させず、次回起動時のポート競合を防げる明示的な停止操作が必要である。

## What Changes

- `mise run stop` を追加し、実行中の Newzsnac スーパーバイザーへ正常終了を要求する。
- 起動時にスーパーバイザーの PID を専用ファイルへ記録し、終了時に自身の記録だけを削除する。
- 停止済みまたは古い PID ファイルだけが残っている場合も、停止コマンドを成功扱いにする。
- PID ファイルの保存先を既定値としてコードに持ち、`.env` または環境変数で上書き可能にする。
- ポート番号やプロセス名を使った一括終了は行わず、Newzsnac が記録したスーパーバイザーだけを対象にする。

非目標は、OS 再起動後の自動起動、デーモン化、無関係なプロセスの強制終了である。

## Capabilities

### New Capabilities

- `runtime-lifecycle`: mise タスクによるローカル実行プロセスの起動状態管理と安全な停止を規定する。

### Modified Capabilities

なし。

## Impact

- `mise.toml` に停止タスクを追加する。
- 設定、スーパーバイザー、停止用エントリーポイント、起動テスト、README が影響を受ける。
- 外部依存関係やデータベーススキーマの変更はない。

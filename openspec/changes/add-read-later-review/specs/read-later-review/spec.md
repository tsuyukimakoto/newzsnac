## Purpose

一覧で選別した記事を「保存済み」と混同せずにあとで原文確認できるよう永続化し、ブラウザ本来のリンク操作と選択項目の一括削除を使える読書工程を提供する。

## ADDED Requirements

### Requirement: あとで読む記事を独立して管理する
システムは、記事ごとに「あとで読む」状態をSQLiteへ永続化し、「保存済み」とは独立したIndexと件数を提供しなければならない（SHALL）。「あとで読む」へ追加された記事は既読として記録しなければならない（MUST）。

#### Scenario: 通常Indexからあとで読むへ追加する
- **WHEN** 利用者が通常Indexの選択記事を「あとで読む」へ追加する
- **THEN** システムは記事を「あとで読む」と既読に記録し、通常Indexの次の記事へフォーカスを移す

#### Scenario: あとで読むIndexを開く
- **WHEN** 利用者が「あとで読む」Indexを選択する
- **THEN** システムは「あとで読む」として記録された記事だけを表示し、「保存済み」の状態にかかわらず件数へ含める

### Requirement: 原文確認の対象を選択する
システムは、「あとで読む」Indexの各記事に一括原文確認の対象を示すチェックボックスを表示し、Indexを読み込んだ時点では表示中の記事を選択済みにしなければならない（SHALL）。チェックボックスの変更は「あとで読む」の永続状態を変更してはならない（MUST NOT）。

#### Scenario: あとで読むIndexを読み込む
- **WHEN** 利用者が「あとで読む」Indexを読み込む
- **THEN** システムは表示中の各記事を一括原文確認の対象としてチェック済みにする

#### Scenario: 一括対象から記事を外す
- **WHEN** 利用者が記事のチェックを外す
- **THEN** システムはその記事を一括原文確認の対象から除外し、「あとで読む」には残す

### Requirement: 原文リンクと一括削除を提供する
システムは、「あとで読む」Indexの記事タイトルを正規URLへの通常のリンクとして表示し、修飾キーを含むリンクの開き方をブラウザの既定動作へ委ねなければならない（SHALL）。システムはチェック済みの記事を一回の操作で「あとで読む」から削除できなければならない（MUST）。一括削除は記事の既読、保存済み、関心の状態を変更してはならない（MUST NOT）。

#### Scenario: Commandクリックで原文を開く
- **WHEN** 利用者が「あとで読む」の記事タイトルを⌘クリックする
- **THEN** システムは正規URLを通常のリンクとしてブラウザへ渡し、タブの開き方をブラウザの設定と操作へ委ねる

#### Scenario: 対象を選択していない
- **WHEN** チェック済みの記事がない状態で利用者が一括原文確認を実行する
- **THEN** システムは一括削除を行わず、対象を選ぶよう通知する

#### Scenario: 選択記事を一括削除する
- **WHEN** 利用者が複数の記事をチェックし、一括削除を実行する
- **THEN** システムはチェック済み記事をすべて「あとで読む」から削除し、既読、保存済み、関心の状態を維持する

#### Scenario: 一括削除に失敗する
- **WHEN** 一括削除操作が失敗する
- **THEN** システムは対象記事を「あとで読む」に残し、失敗理由をIndexへ表示する

### Requirement: あとで読むIndexを消化する
システムは、「あとで読む」Indexで利用者が次へ進んだときだけ、移動前の記事を「あとで読む」から除外しなければならない（MUST）。前へ戻る操作では移動前の記事を除外してはならない（MUST NOT）。

#### Scenario: 次の記事へ進む
- **WHEN** 利用者が「あとで読む」Indexで `j` を押す
- **THEN** システムは現在の記事を「あとで読む」から除外し、次の記事を選択する

#### Scenario: 前の記事へ戻る
- **WHEN** 利用者が「あとで読む」Indexで `k` を押す
- **THEN** システムは現在の記事を「あとで読む」に残したまま、直前の記事へ戻る

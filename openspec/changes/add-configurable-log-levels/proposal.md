## Why

現在の出力には日時付きの `INFO` と `WARN` がある一方、起動状態や失敗はレベルなしで直接出力され、定期ポーリングを必要なときだけ観察する共通の仕組みもない。アプリケーション全体で一貫したログレベルを使い、通常時の動作把握と詳細調査を設定で切り替えられるようにする。

## What Changes

- `DEBUG`、`INFO`、`WARN`、`ERROR` の順序と最小出力レベルを持つ共通ロガーを導入する
- `NEWSZNAC_LOG_LEVEL` で最小出力レベルを設定し、初期値を `info` にする
- Web、収集ワーカー、分析ワーカーの起動完了を `INFO` として出力する
- 収集・分析ワーカーの定期ポーリング結果を `DEBUG` とし、初期設定では表示しない
- 収集、記事分析、推薦など利用者が動作を把握するための完了イベントを `INFO` として維持する
- 継続可能だが注意が必要な情報源取得失敗を `WARN` として出力する
- ジョブ失敗、ワーカー停止、起動失敗などのエラーを `ERROR` として出力する
- 起動状態を含むログ出力を共通ロガーへ統合し、呼び出し箇所ごとの条件分岐でレベルを模倣しない
- CLI、停止コマンド、HTTP API のJSON応答はログではないため形式を変更しない
- 非目標: ログファイル、ローテーション、外部転送、カテゴリ別の個別フィルターは今回扱わない

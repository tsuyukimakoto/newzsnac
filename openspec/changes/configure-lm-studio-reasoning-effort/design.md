## Context

変更理由はproposal.mdを参照する。NewzsnacはLM StudioのOpenAI互換`/v1/chat/completions`を記事分析、全文翻訳、記事問答に使用している。記事分析だけは`reasoning_effort: "none"`と根拠未記録の`max_tokens: 1_200`を明示している。LM Studio 0.4.8以降は同エンドポイントの`reasoning_effort`に対応し、現在のQwen 3.8実機でも`medium`が受理される。

## Goals / Non-Goals

**Goals:**

- 記事分析、翻訳、問答の推論量を、一つの型付き設定で予測可能にする。
- 既存の設定優先順位（`config.ts`、`.env`、起動時環境変数）を維持する。
- 記事分析の推論と最終回答が使った出力量を観測可能にする。

**Non-Goals:**

- ロード済みモデルの能力を起動時に問い合わせて設定値を自動調整しない。
- モデルを自動ロードまたは再ロードしない。
- リクエスト種別ごとに別々の推論設定を持たせない。

## Decisions

### OpenAI互換の`reasoning_effort`をリクエストごとに送る

設定名は`NEWSZNAC_LM_STUDIO_REASONING_EFFORT`とし、値はOpenAI互換APIで使用する`none`、`low`、`medium`、`high`に制限する。既定値は`medium`とする。LM Studioの画面上のロード設定を変更する方法ではなく、各テキスト生成リクエストのトップレベルフィールドとして送信する。

代案としてLM Studio固有の`/api/v1/chat`へ移行する方法があるが、既存の構造化出力とクライアント契約を同時に変更する必要がなく、OpenAI互換APIが必要な機能を提供しているため採用しない。

### 一つのクライアント設定を記事分析、翻訳、問答へ適用する

LM Studioクライアントの生成時にreasoning effortを渡し、すべてのテキスト生成メソッドが共通して使用する。埋め込みAPIには推論概念がないため変更しない。

用途別の設定も可能だが、まず同一の`medium`で実測するため採用しない。将来、観測結果が用途ごとの差を示した時点で分離する。

### 記事分析の最大出力を`8,096`にして利用量を記録する

従来の`1,200`には計測に基づく根拠がないため、利用者指定の`8,096`へ広げる。これは目標量ではなく打ち切り上限であり、モデルが必要な時点で生成を終了できる。応答の`finish_reason`、`usage.prompt_tokens`、`usage.completion_tokens`、`usage.completion_tokens_details.reasoning_tokens`、最終回答の文字数、処理時間、JSON検証結果を一行のJSONログへ出す。記事タイトル、URL、本文、生成内容はログへ含めない。

SQLiteへ観測専用テーブルを追加する案は、スキーマ変更と保存期間の設計が必要になるため今回は採用しない。ワーカーの標準出力を観察し、恒久保存が必要と分かった時点で別途設計する。

構造化ログは1分析につき一行で容量は小さいが、通常運用の標準出力を増やすため既定では無効にする。`NEWSZNAC_ANALYSIS_TELEMETRY_ENABLED=true`の場合だけ分析ワーカーへロガーを渡す。このプロジェクトのGit管理外`.env`では観測を継続するため有効にする。真偽値は`true`と`false`だけを受理し、誤記を黙って無効扱いにしない。

### 設定値は起動時に検証する

文字列をそのまま送らず、許可値との完全一致を確認して型付きの値へ変換する。モデルごとの対応範囲はLM Studioが管理するため、構文上有効でもロード中モデルが対応しない値はLM StudioのHTTPエラーとして既存の失敗処理へ流す。

## Risks / Trade-offs

- [モデルによって対応する推論量が異なる] → 既定値は実機のQwen 3.8で確認済みの`medium`とし、LM Studioのエラー詳細を既存どおり表示・記録する。
- [推論を減らすと一部の回答品質が変化する] → `.env`で`high`へ戻せるようにし、保存済み結果は自動再生成しない。
- [8,096でも推論とJSONを出し切れない] → `finish_reason`とトークン内訳を記録し、推測ではなく観測結果から次の上限を決める。
- [ログに記事内容が漏れる] → 識別情報や生成内容を含めず、数値、終了理由、検証結果だけを記録する。
- [通常運用の標準出力が分析件数に比例して増える] → 既定では無効にし、観測時だけ環境設定で有効にする。

## Migration Plan

1. 設定とクライアント配線を配備し、アプリとワーカーを再起動する。
2. `.env`に指定がなければ、以後の記事分析、翻訳、問答は`medium`で生成する。
3. 分析ログを一定期間観察し、上限到達、JSON成功率、推論量、所要時間を確認する。
4. 問題がある場合は`NEWSZNAC_LM_STUDIO_REASONING_EFFORT=none`へ上書きするか、コードを戻す。SQLiteの変更はない。

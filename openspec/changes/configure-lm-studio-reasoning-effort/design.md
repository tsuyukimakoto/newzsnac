## Context

変更理由はproposal.mdを参照する。NewzsnacはLM StudioのOpenAI互換`/v1/chat/completions`を記事分析、全文翻訳、記事問答に使用している。記事分析だけは既存の障害対策として`reasoning_effort: "none"`を明示し、翻訳と問答はモデルの既定値に任せている。LM Studio 0.4.8以降は同エンドポイントの`reasoning_effort`に対応し、現在のQwen 3.8実機でも`medium`が受理される。

## Goals / Non-Goals

**Goals:**

- 自由文を生成する翻訳と問答の推論量を、一つの型付き設定で予測可能にする。
- 既存の設定優先順位（`config.ts`、`.env`、起動時環境変数）を維持する。
- 記事分析の構造化出力に対する推論無効化を維持する。

**Non-Goals:**

- ロード済みモデルの能力を起動時に問い合わせて設定値を自動調整しない。
- モデルを自動ロードまたは再ロードしない。
- リクエスト種別ごとに別々の自由文推論設定を持たせない。

## Decisions

### OpenAI互換の`reasoning_effort`をリクエストごとに送る

設定名は、記事分析には適用しないことが明確な`NEWSZNAC_FREEFORM_REASONING_EFFORT`とし、値はOpenAI互換APIで使用する`none`、`low`、`medium`、`high`に制限する。既定値は`medium`とする。LM Studioの画面上のロード設定を変更する方法ではなく、各自由文生成リクエストのトップレベルフィールドとして送信する。

代案としてLM Studio固有の`/api/v1/chat`へ移行する方法があるが、既存の構造化出力とクライアント契約を同時に変更する必要がなく、OpenAI互換APIが必要な機能を提供しているため採用しない。

### 一つのクライアント設定を翻訳と問答へ適用する

LM Studioクライアントの生成時にreasoning effortを渡し、自由文生成メソッドが共通して使用する。分析メソッドは設定値を参照せず、引き続き`none`を明示する。埋め込みAPIには推論概念がないため変更しない。

用途別の設定も可能だが、現時点では同一モデルを使用しており設定項目が増えるだけなので採用しない。将来、翻訳と問答で異なるモデルや推論量が必要になった時点で分離する。

### 設定値は起動時に検証する

文字列をそのまま送らず、許可値との完全一致を確認して型付きの値へ変換する。モデルごとの対応範囲はLM Studioが管理するため、構文上有効でもロード中モデルが対応しない値はLM StudioのHTTPエラーとして既存の失敗処理へ流す。

## Risks / Trade-offs

- [モデルによって対応する推論量が異なる] → 既定値は実機のQwen 3.8で確認済みの`medium`とし、LM Studioのエラー詳細を既存どおり表示・記録する。
- [推論を減らすと一部の回答品質が変化する] → `.env`で`high`へ戻せるようにし、保存済み結果は自動再生成しない。
- [分析と自由文生成で設定が異なり分かりにくい] → READMEへ分析は常に`none`、設定は翻訳と問答に適用されることを明記する。

## Migration Plan

1. 設定とクライアント配線を配備し、アプリとワーカーを再起動する。
2. `.env`に指定がなければ、以後の翻訳と問答は`medium`で生成する。
3. 問題がある場合は`NEWSZNAC_FREEFORM_REASONING_EFFORT=high`へ上書きするか、コードを戻してモデル既定値へ戻す。SQLiteの変更はない。
